# DOC_DISCIPLINE — 문서 작업법

> `C:\project\diary`(조각)의 동명 문서를 LinkMemo에 맞춰 승계한 것(원류는 `C:\project\volleyball`).
> 이걸 지키면 "코드와 문서가 따로 노는" drift와 "옛날 수치가 조용히 거짓이 되는" 사고를 막는다.

---

## 1. 결정은 코드보다 먼저 문서에

> 표준 작업 순서 정본은 [`CLAUDE.md`](../CLAUDE.md) §13 — ① 플랜 → ② 문서(코드보다 先) → ③ 개발 → ④ 검증.

- 새 설계 결정은 **코드보다 먼저** 문서에 반영한다 — 루트 `CLAUDE.md`(원칙·기둥·결정 로그) 또는
  `docs/<SYS>_SYSTEM.md`(시스템 상세) + `docs/README.md` 색인.
- "왜 이렇게 정했나"를 남긴다. 특히 **무엇을 안 하기로 했나(제외 결정)** 와 그 이유를 적는다.
  > 예: 비밀번호 전용 필드 = "비밀번호 관리자로 인식되는 것 회피"로 제외(2026-08-14 기획 확정).
  > 회원 시스템 = 로컬 온리 원칙으로 제외(2026-08-14).

## 2. 시스템마다 `*_SYSTEM.md`

- 각 독립 시스템은 자기 설계 문서 `docs/<SYS>_SYSTEM.md`를 가진다(단일 책임 = 단일 문서).
- 문서 상단 또는 `docs/README.md`에 **"구현 현황" 표**를 둬서 설계 vs 실제 코드 간극을 명시한다(✅/❌/🚫/⏸).
- **일관성 검증은 이 구현 현황표를 기준으로 한다.**

## 3. README 색인 (docs/README.md)

`docs/README.md`가 색인이며 다음을 유지한다: 문서 목록 표 · 전체 구현 현황 요약 · 검증 루틴 · 아키텍처 원칙.
새 `*_SYSTEM.md`를 추가하면 **반드시** 색인과 구현 현황 요약에도 추가한다(부록 체크리스트).

## 4. 날짜는 절대화(absolute)

- 결정·변경에는 날짜를 명시한다: `(2026-08-14 결정)` — "최근/얼마 전" 상대 표현 금지.
- 정정 이력을 지우지 말고 **취소선 + 날짜 병기**로 남긴다 — "예전엔 이렇게 생각했다가 이래서 바꿨다"가
  보여야 같은 실수를 안 반복한다.

## 5. 케이스(무엇)와 방법(어떻게)을 분리

- 케이스 레지스트리: *어떤 버그가 있었나·무엇을 검사하나* — 증상 → 원인 → 수정 → 도구.
- 방법론: *어떻게 새 버그를 찾나* — 발견 기법·후속 절차.
- 둘을 섞지 않는다.

## 6. 도메인·라이브러리 사실은 출처로 (추정 금지)

- SDK/라이브러리 API·스토어 정책·법령은 구현 전 **공식 문서로 확인**한다. 기억으로 단정 금지.
- 확인한 내용은 코드 주석·docs에 **출처와 함께** 남긴다.
- 값을 "미확인"으로 적기 전에 저장소(특히 `C:\project\common\BUSINESS_INFO.md`·형제 프로젝트)를 먼저 grep한다 —
  이미 확정된 값을 다시 물어보는 낭비가 실제로 발생했다(BUSINESS_INFO §7, 2026-08-10 기록).

## 7. 커밋 메시지 형식

- `YYMMDD :: [태그] 한국어 작업 요약` — 예: `260814 :: [문서] 설계 정본·docs 체계 수립`.
- 멀티라인 메시지는 heredoc/임시파일 + `git commit -F`로 — 셸 따옴표 오염 회피.
- 문서 갱신을 코드 커밋과 **함께**(또는 먼저) 한다.

## 8. 큰 영역은 인덱스 + 세부 문서로 쪼갠다

한 영역이 커지면 한 문서에 다 넣지 않는다. 인덱스(`docs/README.md`)는 **빠짐없는 목록**이 핵심,
세부(`*_SYSTEM.md`)는 깊이가 핵심. 다른 세션이 인덱스만 읽고도 전체를 돌릴 수 있어야 한다.

## 부록 — 새 시스템 추가 시 문서 체크리스트

```

[ ] docs/README.md 색인 목록 + 구현 현황 요약에 추가
[ ] 정상/엣지 케이스 문서화
[ ] 검증 루틴(README)에 새 명령 추가
[ ] 설계가 CLAUDE.md 기둥/원칙에 영향 주면 CLAUDE.md도 갱신
[ ] 결정에 날짜 병기, 정정은 취소선으로 이력 보존
```
