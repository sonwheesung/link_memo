## 1. 핵심 컨셉

> "링크를 저장하고, 그 링크에 필요한 정보를 함께 기록한다."

```
GitHub (https://github.com)
 ├─ Personal  — ID: personal@example.com · Memo: Personal projects
 ├─ Work      — ID: work@example.com     · Memo: Company account
 └─ Test      — ID: test@example.com     · Memo: Development testing account
```

사이트와 관련 계정을 하나의 공간에서 관리한다. 대표 시나리오: 개인 계정 관리 · 업무 계정 관리 ·
개발자 사이트 모음(GitHub·Stack Overflow·Vercel…) · 쇼핑몰 관리(기획서 §39).

## 2. 사이트 등록

| 항목 | 필수 | 설명 |
|---|---|---|
| URL | **O** | 유일한 필수값 |
| Site Name | X | 미입력 시 자동 제안 |

### 이름 자동 제안

`https://github.com` → `GitHub`, `https://notion.so` → `Notion`. 사용자가 제안값을 수정할 수 있다.

- **도메인 파싱만으로 확정**(2026-08-14) — 오프라인에서도 동작한다. 알려진 도메인 표 + 첫 라벨 capitalize 폴백.
- 페이지 `<title>` fetch는 하지 않는다(프라이버시·복잡도 — CLAUDE.md §14 #5-7).

### URL 정규화 규칙 (2026-08-14 Phase 2 구현 결정)

- 앞뒤 공백 제거 → 스킴 없으면 `https://` 보정 → 호스트명 소문자화.
- 검증은 호스트명 형태(`레이블.레이블`, 점 필수)만 본다 — 존재하는 도메인인지 네트워크로 확인하지 않는다
  (오프라인 등록 보장). 형태가 아니면 `site.invalidUrl` 에러로 저장 거부.
- RN의 `URL` 폴리필은 불완전하므로 **정규식 파싱**으로 구현한다(`features/sites/url.ts`).
- **중복 차단**(2026-08-14 사용자 결정): 정규화된 URL이 기존 사이트와 **정확히 일치**하면
  `site.duplicateUrl` 에러로 저장 거부. 수정 시 자기 자신은 제외. 비교는 정규화 결과의
  문자열 완전 일치 — 경로·쿼리가 다르면 다른 URL이다(`findSiteByUrl`, `features/sites/api.ts`).

### 사이트 아이콘 — ✅ 직접 fetch로 확정 (2026-08-14 · 구현 방식 확정 Phase 3)

- **해당 사이트에서 직접 가져온다** — 구현(2026-08-14): 사이트 홈 HTML을 fetch(5초 타임아웃)해
  `<link rel="icon">`류에서 아이콘 URL을 해석(PNG 우선), 없으면 `origin/favicon.ico` 폴백.
  해석된 **아이콘 URL을 `sites.favicon`에 저장**하고 렌더는 **expo-image 디스크 캐시**에 맡긴다
  (파일 직접 다운로드보다 단순하고, 오프라인 재표시는 디스크 캐시가 담당).
- 렌더 실패(ICO 미지원 등)·미해석 시 **이니셜 기본 아이콘**(테마 색 배경 + 이름 첫 글자) — `components/site-icon.tsx`.
- 외부 아이콘 서비스(Google S2 등)는 🚫 — 사용자가 저장한 도메인 목록이 제3자에게 흘러간다(기둥 2 위반).
  fetch는 **사용자가 저장한 그 사이트로만** 나간다.
- 시점: 사이트 저장·URL 변경 직후 백그라운드로 시도 + 홈 진입 시 미해석 사이트 재시도(세션당 1회).
  **아이콘 실패가 사이트 저장을 막지 않는다.** URL을 바꾸면 기존 아이콘을 비우고 다시 해석한다.

## 3. 계정

하나의 사이트에 **여러 계정**. 계정 수 상한 없음.

| 항목 | 필수 | 설명 |
|---|---|---|
| Account Name | X | 구분용 이름 (Personal / Work …) |
| Username / ID | X | 로그인 ID |
| Memo | X | 자유 메모 |
| Sensitive Memo | X | 메모 숨김 여부 플래그 |

- **모든 필드가 선택** — 사이트만 저장하고 계정 0개도 정상 상태다.
- **Password 전용 필드는 없다**(CLAUDE.md §8). 적고 싶으면 메모에 적는다.

계정 메모는 **1개 + `memoSensitive` 숨김 플래그**로 확정(2026-08-14 — CLAUDE.md §5.
일반/민감 메모 2칸이 아니다).

### 민감한 메모 (MVP = 전체 숨김)

~~사이트 상세의 계정 카드에서 `••••` + 눈 토글~~ → **2단 구조로 정정(2026-08-14 사용자 피드백)**:

| 위치 | 표시 |
|---|---|
| 사이트 상세의 계정 카드 | **`🔒 숨겨진 메모` 상태 라벨만** — 점 표시·눈 토글 없음 |
| **계정 상세 화면**(신설, 카드 탭으로 진입) | 가려진 상태로 시작, **눈 아이콘으로만 내용 확인** |

- 점(`••••`)은 "내용이 있는데 가려짐"보다 "비밀번호 입력창"으로 읽힌다 — 상태 라벨이 명확하다.
- 계정 카드 탭 = 계정 상세(보기). 수정·삭제는 상세 화면의 헤더에서.
- 확인 중에는 전면 광고를 띄우지 않는다(CLAUDE.md §7).
- ⚠ 수정 화면(account-form)에서는 메모가 보인다 — 수정하려면 봐야 한다. 진입 자체가 의도적 행위다.
- 부분 텍스트 숨김은 P2. **숨김은 암호화가 아니다** — 사용자 표기 규칙은 CLAUDE.md §8.

### Open in Browser

`LinkMemo → OS 기본 브라우저 → Website`. 여기까지가 역할이다.

**제공하지 않는 것**: 자동 로그인 · ID/비밀번호 자동 입력 · 앱 내 WebView · 브라우저 세션 관리.

- 브라우저 실행 직전에 광고를 띄우지 않는다(기둥 6).
- URL 스킴이 없으면 저장 시 `https://`를 보정한다. `openURL` 실패(잘못된 URL)는 조용히 삼키지 말고 알린다.

## 5. 검색

검색 대상: **Site Name · URL · Account Name · Username/ID · Memo** 전체.

| 검색어 | 결과 |
|---|---|
| `github` | 사이트 GitHub |
| `work` | Work 계정이 등록된 사이트 |
| `project` | "project"가 포함된 메모의 사이트 |

- 검색 입구는 ~~홈 검색바~~ → **홈 우상단 검색 버튼 하나 → 검색 화면**(2026-08-14 사용자 재정정).
  Search 탭은 없다(조각의 강등 실증 승계 — 검색은 목적지가 아니라 도구다).
- 결과는 사이트 단위로 묶어 보여준다(어느 필드가 맞았는지 힌트 표시).
- **민감(숨김) 메모 본문**: 매치는 시키되 결과 미리보기에 본문을 노출하지 않는다(§3의 숨김 약속과 일관) —
  힌트에 `🔒 숨겨진 메모`만 표시.
- 구현(2026-08-14 Phase 3): 로컬 데이터 소량이라 **JS 필터**(대소문자 무시 contains, SQL LIKE 불요).
  250ms 디바운스. 매치 우선순위 = 사이트 이름 → URL → 계정 이름 → ID → 메모.

## 6. 즐겨찾기

- **사이트 단위**로 등록/해제. ~~전용 탭~~ → **홈 상단 즐겨찾기 섹션이 전부**(2026-08-14 단일 화면 결정).
- 토글 입구는 **사이트 상세 헤더의 하트**(Phase 3 구현). 홈 섹션은 가로 스크롤 카드(아이콘+이름), 탭 시 상세로.
- 즐겨찾기 토글은 `updated_at`을 건드리지 않는다 — 목록 순서가 튀면 안 된다(DATABASE §3).
